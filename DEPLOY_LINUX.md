# Ariel HR (Horilla) — Linux Local Server Deployment Guide

Guide for deploying this project from the Windows dev zip onto a local Linux server
(Ubuntu 22.04/24.04 or Debian 12 assumed; adapt package commands for other distros).

---

## 0. About the zip

The zip was made from the Windows dev folder **as-is**, so it contains some
Windows-only content that must be deleted after unzipping (step 2 does this):

- `venv/`  ← Windows virtualenv, **will not work on Linux** — delete and recreate
- `__pycache__/` folders — Windows-compiled bytecode, safe to delete
- `staticfiles/` (if present) — regenerated by collectstatic

Useful content that carries over automatically:

- `TestDB.sqlite3` — the current database (users, employees, settings)
- `media/` — uploaded files (profile photos, documents)
- `.env` — environment config (must be edited for the server, see step 4)

---

## 1. Install system packages (on the Linux server)

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip unzip
# optional, only if you will compile translations:
sudo apt install -y gettext
```

Python 3.10+ is required (Django 5.2). Check with `python3 --version`.

## 2. Unpack the project

```bash
sudo mkdir -p /opt/arielhr
sudo chown $USER:$USER /opt/arielhr
unzip ariel-dev.zip -d /opt/arielhr
cd /opt/arielhr
```

(If the zip contains a top-level folder, `cd` into it — the folder that has `manage.py`.)

**Now remove the Windows-only leftovers** (from the folder containing `manage.py`):

```bash
rm -rf venv staticfiles
find . -type d -name "__pycache__" -exec rm -rf {} +
```

The `venv` from Windows contains Windows executables and must be recreated on
Linux in the next step. Deleting `__pycache__` avoids stale bytecode issues.

## 3. Create the virtualenv and install dependencies

```bash
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Configure `.env`

Create (or edit) `.env` in the project root:

```ini
DEBUG=False

# Generate a fresh one: https://djecrety.ir
SECRET_KEY=change-me-to-a-long-random-string

# The server's LAN IP and/or hostname
ALLOWED_HOSTS=192.168.1.50,arielhr.local,localhost,127.0.0.1

CSRF_TRUSTED_ORIGINS=http://192.168.1.50:8000,http://arielhr.local:8000

TIME_ZONE=Asia/Kolkata

# Leave DATABASE_URL / DB_* unset to use the bundled SQLite file (TestDB.sqlite3).
# For PostgreSQL instead:
# DATABASE_URL=postgresql://horilla:password@localhost:5432/horilla
```

Notes:
- Replace `192.168.1.50` with your server's actual IP (`ip a` to find it).
- SQLite is fine for a small team on a local server. For 50+ concurrent users
  or long-term production, switch to PostgreSQL.

## 5. Migrate, collect static files

```bash
source venv/bin/activate
python manage.py migrate
python manage.py collectstatic --noinput
```

- If you copied `TestDB.sqlite3` from Windows, `migrate` will say "No migrations
  to apply" and all your data (users, passwords, settings) is already there.
- `collectstatic` is required because `DEBUG=False`; WhiteNoise then serves the
  static files directly — **no nginx needed** for a local deployment.

## 6. Quick test run

```bash
python manage.py runserver 0.0.0.0:8000
```

From another machine on the LAN, open `http://<server-ip>:8000` and log in.
If it works, stop it (Ctrl+C) and set up the permanent service below.

If the firewall blocks it:

```bash
sudo ufw allow 8000/tcp
```

## 7. Run permanently with gunicorn + systemd

gunicorn is already in `requirements.txt`. Create the service:

```bash
sudo tee /etc/systemd/system/arielhr.service > /dev/null <<'EOF'
[Unit]
Description=Ariel HR (Horilla)
After=network.target

[Service]
User=YOUR_LINUX_USER
Group=YOUR_LINUX_USER
WorkingDirectory=/opt/arielhr
ExecStart=/opt/arielhr/venv/bin/gunicorn horilla.wsgi:application \
    --bind 0.0.0.0:8000 --workers 3 --timeout 120
Restart=always

[Install]
WantedBy=multi-user.target
EOF
```

Replace `YOUR_LINUX_USER` (twice) and the paths if you used a different directory. Then:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now arielhr
sudo systemctl status arielhr        # should say "active (running)"
```

The app now starts automatically on boot. Logs: `journalctl -u arielhr -f`

## 8. Backups (recommended cron job)

SQLite backup is just copying one file. Add a daily cron:

```bash
mkdir -p /opt/arielhr_backups
crontab -e
# add this line — daily at 02:00, keeps 14 days:
0 2 * * * cp /opt/arielhr/TestDB.sqlite3 /opt/arielhr_backups/db.sqlite3.bak.$(date +\%Y\%m\%d) && find /opt/arielhr_backups -mtime +14 -delete
```

Also back up the `media/` folder periodically (uploaded documents/photos).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `DisallowedHost` error page | Add the exact host/IP you're browsing to `ALLOWED_HOSTS` in `.env`, restart the service. |
| CSRF verification failed on login | Add `http://<host>:8000` to `CSRF_TRUSTED_ORIGINS` in `.env`. |
| Pages load without styling | You forgot `collectstatic`, or `DEBUG=False` with an old `staticfiles/` — rerun step 5 and restart. |
| `attempt to write a readonly database` | The service user must own the DB and folder: `sudo chown -R YOUR_LINUX_USER /opt/arielhr` |
| Changed `.env` but nothing happened | `sudo systemctl restart arielhr` — env is read at startup. |
| Forgot a password | `venv/bin/python manage.py changepassword <username>` from the project folder. |

## Useful commands

```bash
sudo systemctl restart arielhr      # restart after any code/.env change
journalctl -u arielhr -f            # live logs
venv/bin/python manage.py shell     # Django shell against live DB
```
